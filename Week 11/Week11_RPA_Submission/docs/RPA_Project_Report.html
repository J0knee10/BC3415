Meridian AP FX Exposure Bot

BC3415 Week 11 · RPA project · TagUI v6 · Jonathan Low · ECB rate date 2026-10-23

1. Summary

An RPA bot that does a finance team's morning foreign-exchange routine: it reads the European Central Bank's reference rates from the ECB website, keeps a daily rate history, converts every open foreign-currency supplier invoice into SGD, measures the FX risk, raises alerts and saves screenshots as audit evidence. It is built on idea 2 from the brief ("scrape daily FX rates and append to a CSV") and carried through to the accounts-payable task that the rates are needed for.

2. Business problem

Meridian (the fictional company used in the Week 10 n8n lab) buys from suppliers in Europe, the US, Japan, Malaysia, China, the UK and Australia, and reports in SGD. Before each payment run an AP analyst:

  1. opens the ECB reference-rate page and copies the rate for each currency into a spreadsheet;
  2. works out SGD cross rates (the ECB quotes everything against the euro);
  3. converts each open invoice, sorts them by due date and spots overdue ones;
  4. checks whether any currency has moved sharply, which changes how much SGD to set aside;
  5. saves a screenshot of the source page so auditors can see which rates were used.

That takes roughly 20–30 minutes a day, and copy-typing rates is a known source of errors (a JPY rate of 0.008153 is easy to mistype). It is rule-based, repetitive, done in a browser and a spreadsheet, and has no judgement in it until the exceptions: a good fit for RPA.

3. How the bot works

  1. Load inputs. input/open_invoices.csv (10 synthetic invoices in 7 currencies plus one bad code, XYZ) and input/bot_settings.csv (alert thresholds the AP team can change without editing the script).
  2. Read today's rates. Opens the ECB page, declines the cookie banner, reads the reference date heading and, for each currency, the spot rate using XPath anchored on the table row id (//td[@id="USD"]/../td[contains(@class,"spot")]//span[@class="rate"]). A currency missing from the table (XYZ) is recorded rather than crashing the run.
  3. Evidence. Screenshots of the rate table and the whole page.
  4. History per currency. For each currency the bot clicks through to its chart page and reads the last ~40 daily rates from the page's own chart data (generateChartData(), via a dom step), then screenshots the chart. The chart script sometimes loads late, so the read is retried up to 5 times; this was added after a real failure during testing.
  5. Cross rates and statistics. SGD per unit = (EUR→SGD) ÷ (EUR→currency), for today and every historical date. Day-on-day change, 1-month (22 fixings) average, low and high.
  6. History file. Appends today's rates to output/fx_rates_history.csv only if that ECB date is not already there.
  7. Invoices. Amount in SGD, days to due, bucket (overdue / this week / 30 days / later), and FX risk = extra SGD if paid at the 1-month high.
  8. Alerts. FX move ≥ 0.5% day-on-day or ≥ 2% from the 1-month average; overdue invoices; unsupported currencies.
  9. Report. Builds an HTML report, shows it in the bot's browser and screenshots it; writes one line to output/run_log.csv.

5. Is it right? Independent check

The bot's figures come from scraping web pages, so a second, independent route was used to check them: the ECB also publishes the same rates as an XML file for machines. tools/verify_against_ecb_xml.py downloads it, recomputes every SGD amount and FX-risk figure, and compares them with the bot's CSV.

6. Controls and design choices

  • Read-only. The bot reads a public page and writes local files. No logins, no credentials, no payments.
  • Re-runnable. History is keyed on ECB date; repeating a run does not duplicate rows (run 2).
  • Fails loudly. Missing elements stop a read step with an error instead of producing a zero; an unknown currency becomes an EXCEPTION row for a person to handle.
  • Evidence every run. Screenshots of the table, page, each chart and the report, plus the console log of each run.
  • Settings outside the code. Thresholds live in a CSV the AP team can edit.
  • Human decision kept. The report says it is advisory; FX risk is a planning number, not a hedge instruction.

7. Building it: problems met and fixed

TagUI's last release (v6.110, June 2022) does not run as shipped on Windows 11 25H2 with Chrome 156. Five fixes were needed, now packaged as tools/patch_tagui_2026.ps1 (tested on the original files, safe to re-run):

  1. Chrome rejects TagUI's DevTools websocket without --remote-allow-origins=*: TagUI hung at "listening for inputs".
  2. wmic.exe has been removed from Windows 11; TagUI used it to find and close its Chrome. Replaced with a PowerShell helper.
  3. TagUI's PATH check looks for casperjs but the Windows package ships casperjs.exe: "'casperjs' is not recognized".
  4. find /i resolved to Git's Unix find and scanned the C: drive. Pinned to Windows' find.exe.
  5. Element screenshots were clipped with viewport coordinates, so anything below the fold came out blank. Switched to page coordinates.

In the flow itself: TagUI wraps each step in its own function, so helper functions had to be global; Chrome blocks a web page from opening a local file:// report, so the report HTML is written into a blank tab instead; and the chart-data read got a retry loop.

8. Limits and next steps

  • ECB reference rates are fixed around 16:00 CET (late evening in Singapore), so a 09:00 SGT run uses the previous business day's rate. They are indicative; the bank's dealt rate on payment day will differ.
  • The bot depends on the ECB page layout. A redesign breaks the read steps (loudly); the XML check would catch a silent change.
  • Next: read invoices straight from the AP system export instead of a CSV, schedule it in Task Scheduler at 09:00, and send the alerts file to the team chat (the Week 10 n8n workflow already has a Telegram channel that could receive it).
